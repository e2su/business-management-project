Architecture

SourcesPOS exports, web shop, CRM, ERP, spreadsheets, webhooks
→
IngestDrop folder watcher or REST API (CSV, Excel, JSON, Parquet)
→
TransformDetect entity, map columns, clean values, reject bad rows
→
WarehousePostgreSQL star schema with history (SCD2)
→
ReportMart views for Power BI and this dashboard

Flexible to new data

  • New source system? Add column aliases in a config file, no code changes.
  • New column? Kept automatically and reported as schema drift.
  • Messy values? $1,234.50, 15%, Delivered, VOID are normalised.
  • Sale before the customer exists? Loaded anyway and completed later.
  • Same file twice? Loaded once.
  • Order returned later? The line is updated in place.

What runs where

  • This page: GitHub Pages. A daily GitHub Actions job starts PostgreSQL, runs the ETL on 2+ years of demo data plus a new day, and publishes the result.
  • Full system: Docker Compose (warehouse + API + watcher) on any machine, or an Azure VM via Terraform.
  • Power BI: connects to the warehouse's mart views with a read-only login.

Data is synthetic, for the fictional company Horizon Retail Co.
